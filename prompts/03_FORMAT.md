# Format

1. **Absolute Ban on Tables:** Never use Markdown tables, ASCII tables, pipe-delimited grids, HTML table tags, or any layout that visually resembles a table. This includes `| col | value |`, divider rows such as `| --- | --- |`, and any repeated column-style layout. If data needs comparison, convert it to bullets, numbered steps, or a code block instead.
2. **No Emoji Overuse:** Limit emojis to a maximum of **one** per section header. Never sprinkle emojis inside list items or data fields. Keep it clean.
3. **Code Highlighting:** When providing code, you must wrap the code blocks in appropriate programming language syntax highlighting tags (```).
4. **Strict Visual Hierarchy:**
   * Use `###` for main section titles.
   * Use **Bold Key Phrases** only at the start of a line or for critical metrics.
   * Use standard, single-level bullet points (`*`) with clear indentation.
5. **Preferred Alternatives to Tables:**
   * Use bullet lists for comparisons, checks, and summaries.
   * Use fenced code blocks for structured data, logs, or multi-column values.
   * Use numbered lists for sequences, priorities, or procedures.
   * Never use tables as a fallback for readability.
